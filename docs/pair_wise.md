我直接解释这个问题。                                                                                                   
                                         
  resolve_independent_branch_pts 的作用                                                                                    
   
  当一个 begin...end 块里有多个并列的 conditional/case 语句时，CFG 需要知道它们之间的执行顺序。比如：                      
                                                            
  begin
      if (A) x = 1; else x = 2;   // 分支点 node 5
      if (B) y = 1; else y = 2;   // 分支点 node 13
      if (C) z = 1; else z = 2;   // 分支点 node 27
  end

  这三个 conditional 是同一层级的独立分支点（independent branch points），它们按顺序执行：先 if(A)，再 if(B)，再 if(C)。   
   
  旧实现（N-tuple）                                                                                                        
                                                            
  res = list(combinations(self.ind_branch_points[idx], r=len(self.ind_branch_points[idx])))
  self.edgelist += res                                                                                                     
   
  combinations({5, 13, 27}, r=3) 产生 [(5, 13, 27)]——一个 3 元组。                                                         
                                                            
  make_paths 处理 edgelist 时取 edge[0]=5, edge[1]=13，把这个 3 元组当成一条从 node 5 到 node 13 的边。但 node 27          
  被完全忽略了。
                                                                                                                           
  更严重的是，当 find_basic_block 把 node index 映射到 block index 时，(5, 13, 27) 可能映射成 (block2, block6)——跨越了多个 
  arm 的边界，产生了不应该存在的跨 arm 连接。比如 node 5 在 arm=0 body 里，node 27 在 arm=2 body 里，这条"边"让 CFG
  图里出现了从 arm=0 直接跳到 arm=2 的路径。                                                                               
                                                            
  新实现（pairwise）                                                                                                       
   
  sorted_pts = sorted(self.ind_branch_points[idx])                                                                         
  for i in range(len(sorted_pts) - 1):                      
      self.edgelist.append((sorted_pts[i], sorted_pts[i + 1]))
                                                                                                                           
  对 {5, 13, 27}，产生 [(5, 13), (13, 27)]——两条标准的 2 元组边。                                                          
                                                                                                                           
  这正确表达了顺序执行语义：node 5 执行完后流向 node 13，node 13 执行完后流向 node 27。每条边都是标准的 source→target      
  格式，make_paths 能正确处理。                             

  为什么 N-tuple 是错的

  ┌───────────────┬─────────────────────────────────────────────────────────┬─────────────────────────────────────────┐    
  │     问题      │                         N-tuple                         │                Pairwise                 │
  ├───────────────┼─────────────────────────────────────────────────────────┼─────────────────────────────────────────┤    
  │ 语义          │ 把 N 个点打包成一个"关系"，含义模糊                     │ 明确的顺序流：A→B→C                     │
  ├───────────────┼─────────────────────────────────────────────────────────┼─────────────────────────────────────────┤
  │ make_paths    │ 只取前两个元素，丢失后续节点                            │ 每条边都被正确处理                      │
  │ 处理          │                                                         │                                         │
  ├───────────────┼─────────────────────────────────────────────────────────┼─────────────────────────────────────────┤
  │ 跨 arm 连接   │ (5, 13, 27) 被解释为 node5→node13 的边，但 node13       │ 每条边只连接相邻的分支点，不会跨越 arm  │
  │               │ 可能在另一个 arm 里                                     │ 边界                                    │
  ├───────────────┼─────────────────────────────────────────────────────────┼─────────────────────────────────────────┤
  │ 路径完整性    │ 中间节点（如 node 27）永远不可达                        │ 所有节点都通过链式连接可达              │
  └───────────────┴─────────────────────────────────────────────────────────┴─────────────────────────────────────────┘

  简单说：旧代码试图用一个 tuple 表达"这些点是同级的"，但 make_paths 把它当成了一条边来处理，语义完全错误。新代码用标准的 2
   元组边链表达顺序流，和 CFG 的其他边格式一致。
